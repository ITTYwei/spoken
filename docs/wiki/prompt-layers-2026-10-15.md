# 主教练提示词分层与英语范围

## 本次行为

自由聊天也仅限英语学习与口语练习。英文日常交流可作为口语练习，中文日常话题可引导为英文表达；编程、业务咨询等无关请求简短说明范围并引导回英语，不展开解答。与练习有关的选课、数字人、音色、档位和偏好管理仍可正常调用既有业务工具。

## 消息结构

SYSTEM 经原脚手架的 turn_policy 入口注入，顺序为 system_rules（稳定规则）与 level_policy（可信等级）。等级只决定表达难度，不决定用户要学习什么。L1/L2 的英文后附中文含义，知识讲解可用易懂中文，允许国际音标。固定示例不代表所有等级都使用同样语言。

USER 仍先放可裁剪的历史/记忆，再放不可裁剪的当前数据：

```text
<session_context>
{跟读证据、教学建议、上轮结果、已播目标、人设、学习请求与当前课程背景}
</session_context>
<user_input>
"本轮实际原话"
</user_input>
```

字段由 JSON 编码，额外转义 <、>、&；例如用户说出结束标签也不会关闭外层块。它用于隔离数据边界，不替代工具鉴权或业务规则。

教学动作和结果码只在元数据中，不再拼成 SYSTEM 的本轮命令；模式用中文背景描述，版本和最近课内部编号不再交给主对话提示词。可信工具上下文仍照旧传递真实版本与主体，权限不依赖模型读到的字段。

原话在英语范围和系统边界内优先于旧任务、历史和教学建议。真实跟读问句只是素材，不回答其问题、不写入个人偏好；如果用户在跟读途中问“这句什么意思”或提出新学习需求，则先回答。建议不强制执行；有可靠证据才温和纠音。

“我想学音标”保留为本场学习背景；下一轮“能举例吗”可继续关联。新请求覆盖旧需求，学习请求与完整课程仍在 required 上下文中，不依赖模型记忆，也不会随历史被裁掉。

## 实现边界

ReplyPromptBuilder 负责纯文本分层与编码；TeachingPreparation 只通过领域服务读取课程和教学背景；ADK、Runner、模型客户端和框架适配代码均未修改。生产 spoken-server.yml 同步范围、元数据和参考策略准则；模型参数、结构化输出和播报协议不变。

## 场景、当前任务与优先级补充

YAML 主教练 instruction 精简为身份、业务工具约束与 turn_policy 注入入口，教学、范围和语言要求统一由 ReplyPromptBuilder 管理，避免两处重复维护。SYSTEM 是消息角色，system_rules 是正文分区，仍可同时出现在日志里。

任务优先级：业务边界与真实证据 → 本轮明确需求（包括暂停、拒绝和知识提问）→ 有可信跟读证据时的已播任务反馈 → 课程/场景/本场学习背景 → 教学参考与历史。level_policy 独立控制表达难度，不替用户选任务。

session_context.current_task 提供实际播报确认的动作、自然语言说明、目标句、问题及纠音重试次数，不能用 suggested_target 冒充学员已经听到的任务。background.对话场景保留真实 scenarioId，并区分自由英语、文本课程和指定角色练习；课程里也可能暂时跟读或问知识。

同一句首次示范不算重试，默认最多两次纠音重试。有可靠具体发音证据时，每次只指导一个细节，用“更清楚的读法是……”示范；用户提出新问题时优先解答。达到上限后，提示模型结束该句纠音、不再邀请重读，换句或回到话题。缺乏证据时不编造发音错误。

SpokenTaskResolver 新增带冻结旧任务的重载，流式与整段播报完成均使用它。同句换大小写或句末标点也继承重试次数；即使模型在 RESPOND 建议下再次邀请同句，也不会把次数清零。换新目标从零开始，没有明确邀请不创建跟读任务。计数在确认播报后提交，被打断的邀请不计入。

边界：提示词是模型行为约束，计数修复与策略上限不能保证供应商模型绝不说出超额邀请；此改动不替换已经生成的台词，尚未做真实语音模型联调。
