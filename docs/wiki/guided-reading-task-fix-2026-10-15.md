# 空原话跟读开场修复（2026-10-15）

## 问题与根因

手机点击跟读按钮后没有真实语音，因此 user_input 正常为空；不能伪造一条用户发言。此前仅在 session_context 的背景中写“生成新句”，同时 SYSTEM 明确要求背景只是数据，不作为命令。实际日志中的模型因此返回普通开场，未提供唯一英文目标和邀请，业务护栏两次拒绝后抛出 Retries exhausted。模型请求成功只代表服务完成生成，不代表生成结果符合教学任务。

## 本次修改

- ReplyPromptBuilder 独立生成可信的 reply_task，通过原 turn_policy 进入 SYSTEM。明确立即示范，不等待再次发言，不先询问想聊什么。
- 首句及后续新句仍由模型根据等级、学习请求和情境生成；题目不写死。保持目标唯一、含义说明与明确朗读邀请。
- TeachingPreparation 仅在用户已开启情境跟读且本轮计划是跟读时附加任务；知识解答、暂停和普通交流不会被该任务覆盖。
- 通过、次数用完、缺评测及同句重试使用不同的任务说明，真实目标与证据仍从数据读取，不能将用户或教材文本提升为系统指令。
- 第一次结果不合规时，第二次 SYSTEM 明确说明重新组织完整示范；仍只重试一次，不放宽评测和目标校验，不回退固定句库。
- 删除稳定策略中的重复跟读段落，预算按本轮实际发送的 SYSTEM 计算，完整课程和最近八句照常保留。
- 沿用 IChatService、ADK 和既有工具隔离，不修改框架，不创建新的模型客户端，不新增用户聊天记录。

## 验证记录

本地相关回归 112 项通过，覆盖空按钮输入、日志中普通聊天开场被护栏拒绝后的有限重生成、不同重生成策略、真实知识提问旁路、三次纠音上限、完成播报才提交和完整课程预算。

新增 GuidedReadingTaskLiveTest：通过真实装配节点、配置的模型与短会话验证 L1/L2 首句和 L2 下一句，存储身份使用替身，不访问用户数据库和数字人；默认不发送网络请求。显式在线运行被自动审批拒绝，理由是配置目的地尚未获准接收内部提示词及业务规则，因此本次没有取得真实模型结果，不能将本地替身回归视为真人或在线模型验收。

本次仅改后端，手机协议不变，无需重新打包。IDEA 后端需要重启加载；随后关闭再打开跟读触发新的生成。未执行生产部署。
