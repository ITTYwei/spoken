## 六级教学水平

| 等级 | 对话策略 | 开场脚本档位 |
| --- | --- | --- |
| L1 | 中文支持，单词或短语 | LOW |
| L2 | 中文为主，简单短句；未知用户起点 | LOW |
| L3 | 简单英语，必要中文解释 | MID |
| L4 | 日常英语为主，允许中文帮助 | MID |
| L5 | 自然英语，按需中文澄清 | HIGH |
| L6 | 更丰富但简短的英语，按需中文澄清 | HIGH |

这是产品教学等级，不是 CEFR 认证。等级不进入客户端展示。开场和第一轮共享创建时冻结的六级快照；场景难度和旧词数多数票不再直接证明用户能力。

升档只在新会话开始时检查：

- 最近 30 天，最多最近 10 场已关闭会话。
- 至少 3 场、20 条去重的独立有效回答。
- 观察结果必须为 `ANSWERED`、独立回答且置信度至少 0.85。
- 总体及最近三个有效会话各有至少 80% 的证据支持下一等级。
- 每次最多升一级，CAS 更新防止并发重复升档；升级前的证据不能再次推动升级。
- 少于 8 个词或混合中文的回答，候选等级最多 L3；少于 16 个词最多 L4。词数只限制证据上限，不自动加分。

本场水平固定，求助时可以立即增加中文支持。拒答、短答、跟读分数和一次困难不会自动降低长期水平。首版没有实现长期自动降级；L1 也不由一次失败自动赋予。

发音分仍用于发音评测展示，和自由回答的能力证据分开。客户端传入的 `expectedText` 不能指定教学跟读目标，目标取自服务器上一轮任务。

## 每轮唯一任务与未回答处理

| 上一任务与本轮输入 | 行为 |
| --- | --- |
| 问答：正常回应 | 先回应意思，只问一个问题，等待回答 |
| “不想回答／不想读／跳过” | 温和接受，换一个轻松问题，不降级、不追读 |
| “不知道／听不懂” | 中文帮助，简化或更换一个问题 |
| “我不会说／不会读” | 给一个固定跟读示例，沿用可识别的话题，不同时提问 |
| 固定目标跟读，可信错词且低于 80 分 | 只纠正一个可确认的问题，最多两次重试 |
| 低分但没有可信错词 | 不编造发音错误，放下原目标，换一个问题 |
| 跟读完成 | 结束跟读，再进入下一项问答任务 |
| 空识别结果 | 不判定能力不足，温和提供一个选择问题 |

纠音证据要求分数有效、错词属于服务器目标、预期读音非空且不同于实际、错词置信度至少 0.8。自由对话分数不会触发纠音；打字不能证明读音。

模型问答输出经过逐句守卫：过滤跟读指令和能力评判词，最多两个陈述、一个问句，问句后停止追加。正常结束但没有问句时补一个安全问题；取消和异常不补问句。每句最多 1024 字符，保持第一句可以在整段模型回复结束前进入 TTS。

上一问题和输入时间在本轮准备时保存快照，后台观察不会错用下一轮的问题或完成时间。未回答、部分回答和偏题通过当前提示词明确处理；后台观察只形成能力证据，不阻塞当轮播报。

## 上下文裁剪

- 每轮重新建立短生命周期 ADK 会话，从业务历史组装输入；完成、错误和取消均清理，不累积旧教学 Prompt。
- 当前等级、唯一任务、上一任务和当前输入优先，旧历史仅是引用数据，不能覆盖当前规则。
- 数据库查询最多 32 个已完成播报的问答组；最近最多 6 组保留原文，较早最多 5 条用户短摘录，每条最多 100 字符。
- 跟读和角色扮演历史明确标记为练习素材；较早摘要排除练习输入。练习里的偏好句不能当成真实个人事实。
- 原文按完整问答组裁剪，优先保留较新的组；不留下孤立助手消息。
- `spoken-ai.context.input-budget: 6000` 使用 UTF-8 字节数加开销作保守容量估算，预留 2500 给系统规则。它不是精确 tokenizer 计数。
- 调模型前再次检查实际转换后的消息容量；当前必需输入过大时明确报错，不静默截断意思。
- provider 失败时保留当前规则、降级可选资料；日志记录容量、来源数量和降级类型。

首版摘要采用确定性摘录，不额外调用摘要 LLM，也不把模型推断保存为事实。超过查询窗口的旧对话仍在数据库，但不全部带入本回合。

## 长期记忆

首版只提取明确的简单偏好、学习目标和持久语言支持要求。例如“我喜欢咖啡”和“我不再喜欢咖啡”使用同一事实键覆盖；复杂条件句、临时情绪、角色扮演和跟读内容不推断成现实事实。

每条记忆保存可信主体、事实键、来源会话和回合、确认类型、确认与过期时间。普通事实保留 180 天，语言支持 30 天；按当前主题只召回最多三条相关明确记忆。旧回合迟到写入不能覆盖新回合更正；写入也必须晚于主体遗忘边界，删除后迟到的旧请求不能让事实复活。

“忘掉咖啡”“忘掉所有记忆”删除对应记忆，并在同一事务设置历史召回边界。边界前的原文不再注入上下文，防止重新带回已忘内容；即使当前在跟读，遗忘指令也生效。这里删除的是记忆及其召回资格，原始业务记录仍按原有数据保留机制保存。

## 持久化与完成边界

新增 `V12__teaching_context_memory.sql`：

| 表 | 用途 |
| --- | --- |
| `learner_profile` | 稳定等级、最近升级时间及遗忘边界 |
| `learner_answer_evidence` | 去重的近期能力观察 |
| `conversation_teaching_reply` | 每轮动作、固定目标、结果与已完成播报内容 |
| `agent_long_term_memory` | 明确记忆及来源和过期时间 |

新表 `created_at`、`updated_at` 均为 DATETIME，使用 CURRENT_TIMESTAMP 及更新默认值。V12 已在真实测试启动时应用到当前开发数据库，后续不要修改已应用迁移的内容。

文本生成结束和媒体结束分别处理。只有当前轮次媒体正常结束后提交教学任务和有效回复；整段回退也等待媒体结束，不将 `/say` 受理当成已播放。打断清空未确认任务，旧轮次迟到数据不能提交新任务。

这里的“完成”指 OpenTalking 服务端媒体排空。当前协议没有手机扬声器实际播放完成确认，不能把服务端边界当成用户已听完的严格证明。
