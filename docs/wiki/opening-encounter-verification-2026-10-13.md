# 开场 opening_v2：首次认知与再次连续性

实施日期：2026-10-13。开场继续使用规则与本地模板，走 `/say` 脚本播报，不调用首句 LLM。当前已替代旧的“FIRST / RETURN / PLAN / RESUME / STREAK / DEFAULT”优先级。

## 首次完整介绍

当前数字人没有名称，播报如下四句：

> 你好，我是你的英语口语搭子。你可以和我随便聊聊，也可以告诉我想练什么。没听懂、不会表达，或者想换话题，都可以直接告诉我。先打个招呼吧，中文或英文都可以。

这是身份、用途、帮助和开始方式各一句。结尾只有打招呼这一项开始动作，没有同时要求跟读或回答问题。首次产品介绍统一用中文，历史稳定等级仍冻结给后续教学。首次没有上一问题，不把用户打招呼当作未回答。

首次条件：对话历史及介绍记录均读取成功，没有有效用户对话，且从未完成首次介绍。已有真实对话的老用户使用再次招呼。查询失败不冒充首次，也不声称“上次聊过”，降级到普通招呼。

## 再次进入与可靠续聊

再次进入使用五份中文或英文变体。LOW/MID 开场使用中文选择，HIGH 使用英文选择并继续允许后续中文求助。没有可用话题时，例如：

> 嗨，又见面啦！今天有什么想聊的，或者想练的？

续聊只能来自最近同场景的真实、已完成回复的用户回合。首版支持明确表达，例如“下次聊旅行”“我们下次再聊音乐”。不从普通偏好句、最后一个问号、模型生成摘要或旧 `resume_evidence` 非空值推断待聊事实。当前白名单为旅行/旅游、音乐、电影、美食、咖啡、运动、周末安排。

经确认的示例：

> 嗨，又见面啦！上次我们留了“旅行”。今天想接着聊，还是换个话题？

真实原话与保存的主题必须一致，回合必须属于该会话、不是跟读素材，并且已经正常完成回复。话题状态需为 OPEN，来源在最近 30 天内；不同场景、已结束、敏感状态、没有来源原话、被遗忘边界排除的内容均不可用。

“聊完了”“换个话题”“不想聊”“不要提”“隐私”等明确撤回表达，会关闭本场待聊资格。写入按来源回合顺序校验，旧回合迟到不能重新打开已经关闭的话题。首版保守白名单可能跳过其他普通话题，此时正常招呼，不强行猜测。

轮换采用主体 + 场景 + 情境哈希偏移与当地自然日，五个连续自然日不重复。同一天重复进入使用同一文案；同一会话重试沿用冻结快照，不换句。

## 数字人名称

不再从场景角色 Amy/Alex 或形象 ID 推出名字。名称配置绑定当前选中的 `avatarId`：

```yaml
spoken-ai:
  opening:
    avatar-names: {} # 当前未命名，省略名字
```

以后可在此映射明确名称，例如 `anchor: 小安`。未指定形象时使用和 OpenTalking 驱动一致的默认形象。配置名称必须通过空槽位、问句、控制符和压力词校验。

已有介绍记录且数字人 ID 或明确名称发生变化时，只增加“嗨，我是小白。”这样的简短名字介绍，不重复功能。新形象没有名称时，直接正常招呼。

## 记录与重连

新增 V13 迁移：`conversation_opening_encounter` 以可信主体为主键，保存首次介绍完成时间、最近完成开场的数字人及会话；`training_session` 增加明确待聊来源回合与状态。所有新审计字段使用 DATETIME + CURRENT_TIMESTAMP。

主体键为 `user:<id>` 或 `device:<id>`。当前入口仍是匿名身份适配，所以实际按设备记录；将来认证入口返回可信账号主体后，接口和 SQL 已按账号隔离，不通过客户端自报账号或设备绑定猜测登录人。

介绍记录在 OpenTalking 正常媒体结束后更新，不把空会话、建会话、`/say` 受理当成听完介绍。因此用户只听完介绍且没发言，再次新建会话也不会被当成首次。请求下发失败可以重试；受理成功后的同一会话重连和重复 `/opening` 返回 `already_spoken`，不会重开场。

安卓 `retryMedia()` 对仍存活的会话执行原会话重连，复用同一个 sessionId 和后端开场标记；没有改动安卓接口。如果 OpenTalking 已关闭会话，客户端会重新取号，这是新会话，会使用简短再次招呼。跨新会话原地恢复未完成对话还需要恢复凭证及媒体状态协议，当前不把重新取号伪装成同一会话恢复。

“完成”仍指服务端媒体排空，尚无手机扬声器实际播完回执。首介绍中途被关闭而未正常结束，下一次仍可补完整介绍。
