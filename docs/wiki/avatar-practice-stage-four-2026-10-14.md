# 第 4 步：继续课程与 Agent 切换

## 实际改动

每个新业务会话仍从自由对话开始。后端读取账号真实最近课程，冻结本场开场文案；点击开始后数字人询问继续或自由聊，手机同时提供点击入口。询问仅在对应真实播放完成事件到达后成为待选择任务，绑定回复编号和练习版本。被打断或已切换的询问不再激活任务。

明确“继续”可以使用真实最近课；“好”需要已经听完的待选择任务。没有最近课、不明确的课名、引用、跟读和角色扮演不会自动选课。普通非继续选课必须明确命中课程别名，不能把“今天练面试”映射到烹饪课。

Agent 查询目录和状态后调用 `selectPractice` 或 `continueRecentLesson`。成功经同一个 PracticeCase 更新状态，发布 `practice.changed`，手机直接更新模式。模型未尝试写工具时，只对有限短选择做业务规则兜底；工具失败不重试。最终口头回应由真实执行结果决定。

## 保留脚手架的可信上下文

沿用 YAML → `ToolCallbackProvider` → Spring AI `@Tool` → Case → Domain，调用仍经 `IChatService` 和现有 ADK Runner。每轮捕获账号主体、业务会话、轮次、原话、待选择状态和版本，并携带取消活性检查。

短 ADK 系统消息暂携服务端随机标识；MySpringAI 转为 Spring AI ToolContext 后剥离该标识。模型、用户消息、TTS 和工具参数 schema 都不接收业务身份。工具不依赖请求线程的 AccountContext。结束、失败及取消释放注册项。

适配器兼容 ADK 返回普通 ChatOptions 的情况，复制成支持工具上下文的模型选项；真实模型验证已通过此路径。Spring Bean 使用不同的入口与 Provider 名称，避免命名冲突。

## 验证

- 真机退出到后台再进入：默认自由对话，开场询问上次真实课程，点击继续后第一题和模式生效。
- 真实模型在线测试通过现有 YAML、装配节点和 ADK Runner 执行课程选择与自由切换；验证的是实际 Case 状态变化，持久化替身隔离用户数据。
- 定向测试覆盖账号不匹配、过期版本、异步线程身份、取消后调用、重复成功与失败、“好”的播报前置条件、引用/跟读及模型漏调用兜底。
- 工具结构化结果不会作为台词输出；动作回合在执行完成后播报，普通课程回答维持流式响应。

纯 HTTP、未完成媒体准备的额外文本/语音联测未通过：该测试会话为 QUEUED，文本流入口返回 `text_stream_begin_failed`。不能据此声称完整麦克风 → ASR → 工具 → 播放链路已验收；真实声音体验仍需在媒体就绪的手机上体验确认。
