# 教学策略作为参考，学习请求优先保留

## 为什么改

以前的 TeachingPolicy 根据关键词、中文输入和等级概率决定唯一动作，提示词要求模型服从，过滤器再按动作删句。三层叠加时，“我想学音标，音标有哪些”会被中文必跟读拦住，模型无法完整回答。

现在由模型理解用户的实际需求；服务端只整理可信事实、教学参考和业务边界。TeachingPolicy、ReplyPromptBuilder、TeachingReplyGuard 及保留为业务工具护栏的知识请求识别器，合计从 611 行减到 252 行。

## 当前流程

1. 手机语音识别得到用户原话。
2. 跟读证据准入仅核对已播目标和实际输入，不相符或含额外询问内容时按普通发言处理。保守识别可能放过部分 ASR 错词，但不会凭词重合对知识问题纠音。
3. TeachingPolicy 返回参考建议。删除纯中文必跟读、L1/L2 随机抽样、拒绝/求助关键词强制分流、英语知识关键词教学路由与截短目标逻辑。知识关键词只供业务工具防误操作使用，不决定模型如何回答；普通输入统一建议 RESPOND，不强制 QUESTION 或 READ。
4. 当前原话和本次学习请求放入 USER 必需段；已播任务及评测只是参考。SYSTEM 明确先理解请求，先回答知识，再适时追问或安排练习。
5. 模型通过现有 IChatService、ADK 装配链路组织回复。跟读素材和业务工具的原有隔离、账号校验、版本与去重机制保留。
6. 文本护栏只去掉对错符号、限制异常超长输出；不再用两句话或一个问题上限截掉知识解释、音标、例句和中文译意。
7. 真实播报完成后，只有唯一英文目标和明确跟读邀请都实际出现，才登记下一轮跟读任务；“可以这样说”和“不需要跟读”不会创建跟读任务。

原有结果码保留兼容数据库与历史记录；新增 RESPOND 动作用枚举定义。旧 draw 重载只保留参数校验以兼容调用，已经不产生概率行为。

## “我想学”怎样避免被裁剪

参考 walissh-server 的 TaskProvider 和稳定任务上下文：原始任务独立于普通历史保留，不依赖短生命周期 ADK 会话。没有移植其框架代码。

本项目在 TeachingStateAggregate 保存当前会话学习请求完整原话，TeachingPreparation 每轮将它放到 currentInstruction 的必需段。ChatContextService 先给必需段留预算，再裁剪普通历史和记忆。若必需段超预算，明确失败，不截断关键请求。

例如：

- 第一轮：“我想学音标，音标有哪些？”→ 保存本次学习请求，模型先介绍类别。
- 下一轮：“能举例吗？”→ 当前原话与音标学习请求一起发送，普通历史被裁掉也能继续。
- “我想学过去式”→ 新原话替换旧请求；以最新需求为准。
- “我不想学了 / 换个话题”→ 清空本次固定学习请求。

只记录明确学习诉求作为数据，不据此决定动作或学习等级，不默认写入长期偏好。引用和实际跟读素材不更新目标；另一会话不共享；取消播报不删除用户已经说出的请求。新请求优先于旧目标。原话以 JSON 引用放 USER，不提升成 SYSTEM 指令。

## 验证

67 项检查通过，覆盖语音入口、跟读可信证据、问句素材隔离、工具与账号规则、实际任务提交、完整解释输出，以及多轮学习请求的保留、更换、结束、旧轮次和会话隔离。

通过当前配置模型与原 ADK 链路实测四条：词义解释、过去式问题、音标分类，以及带学习目标上下文的元音举例。它们均回答实际问题，没有强制跟读；音标和较长解释可进入实际播报文本。测试核验的是意图响应与数据流，不代表所有语言知识内容已经经过专家审核；具体音标体系和术语准确性仍依赖模型。

本轮保留既有业务工具安全隔离。自动审批拒绝了另一个删除解答工具隔离分支的尝试，理由是可能产生课程/偏好副作用；最终没有执行该删除，也未更改框架。

IDEA 后端需要重启并新建对话加载代码；本次没有重装手机或进行真机对话，局域网连接保持现状。
