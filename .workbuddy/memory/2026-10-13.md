## 梳理「用户 ↔ 数字人」对话全流程并出图

**目的**：用户要求查清一次对话经过哪些领域、如何编排，并绘制流程图。

**结论（编排主线，llm-owner=agent）**
- 建会话：`ConversationCaseImpl.create` → 关旧会话 + 睡 800ms（单 GPU 槽让位）→ `IConversationService.createSession` → 适配器 POST /sessions → `awaitReady` 每 400ms 轮询 ≤15s → `GET /ice-config` + `POST /offer` 换 SDP → `GET /events` SSE → `POST /opening`（`markOpeningSpoken()` 原子幂等）→ 脚本轨 `/say`。
- 一轮对话（`POST /voice`）：App 上传 AEC3 后裸 PCM → `WavEncoder` 封 WAV → 上游 `/transcribe`（只识别）→ 落回合 + 推 `stt.final` → pronunciation 域评测 + 落库 + 推 `assessment.done` → learner 域判档位 → `ReplyPromptBuilder.build` → agent 域 `IChatService.handleTextStream`（ADK Runner，模型 bonsai-2-27b，reasoning-effort=none）→ conversation 域 `streamReply` 经 WS `/text_stream` 下发 TTS → 上游 `subtitle.chunk`/`speech.ended` 驱动 SSE → 回填回合 `assistantText`。
- 默认 `spoken-ai.reply.streaming-enabled=true` 走 WS `/text_stream` 增量；置 false 回退「收齐整段一次 /say」。

**领域清单（8 个）**：conversation / learner / pronunciation / scenario / identity / practice / agent / shared。
**分层**：trigger → case → domain → infrastructure（端口在 domain 声明，infra 实现）。
**交互型领域只在一条链路里出现**：identity + practice 仅用于开场白素材（OpeningPreparation），不在对话主链路。

## 调研「系统提示词能否在业务中动态替换」（核实 ADK 0.5.0 源码）

**结论**：能，三条路，均已核对 `google-adk-0.5.0-sources.jar` 源码。

1. **占位符模板（推荐）**：`LlmAgent.Builder.instruction(String)` → `Instruction.Static`；运行期 `Instructions.processRequest` → `InstructionUtils.injectSessionState` 用 session state 替换 `{key}`。支持 `{key}`、`{app:|user:|temp:key}`、`{artifact.xxx}`、`{key?}`（可选）。**非可选占位符找不到值 → 抛 `IllegalArgumentException("Context variable not found: xxx")`，整轮失败**；正则 `\{+[^\{\}]*\}+`，指令里任何 `{...}`（如 JSON 示例）都会被当占位符。
2. **`Instruction.Provider`**：`Function<ReadonlyContext, Single<String>>`，每轮现算，`canonicalInstruction` 返回 bypassStateInjection=true → **不做占位符替换**。要改 `AgentNode`（yml 表达不了）。Provider 里只有 ReadonlyContext（session state），拿不到 case 层 VO。
3. **重新装配**：`ArmoryService.acceptArmoryAgents(List<AiAgentConfigTableVO>)` 是 public，`AbstractArmorySupport.registerBean` 同名先摘后注册 → 支持重复装配热更。

**灌 state 的两个入口**：`BaseSessionService.createSession(appName, userId, state, sessionId)`（教学链路每轮新建 session，最省事）；`Runner.runAsync(userId, sessionId, msg, runConfig, stateDelta)`（长会话）。

**链路**：`instruction` 最终经 `LlmRequest.Builder.appendInstructions` 落到 `systemInstruction` → SystemMessage。

**建议**：每轮变的档位/语言/任务继续保持现状走 `ReplyPromptBuilder` → user 消息（CURRENT TURN）；只有「换人格/系统级规则」才用占位符方案，需给 `IChatService.handlePreparedTextStream` 加重载把 state 透给 `createSession`。**本次只做分析，未改代码。**
